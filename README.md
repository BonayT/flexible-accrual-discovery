# Flexible Accrual Discovery

End-to-end validation that the AST-based approach (Approach C) handles 5 real customer pains for flexible accrual in Factorial.

## Context

Romano proposed an approach where AI compiles accrual rules into a deterministic AST at compile time, and the backend executes it at runtime with zero LLM calls. This repo validates that approach against 5 real customer pains.

## What's here

- **`lib/ast/`** — Evaluator, facts resolver, and period iterator copied from [Romano's POC](https://github.com/factorialco/flexible-accrual-poc) (~280 lines of pure Ruby, no deps)
- **`lib/factorial/`** — Fake models (Structs) simulating Employee, Contract, Leave, Allowance + `AccrualFactBuilder` that bridges Factorial models → facts hash for the evaluator
- **`test/`** — 5 customer pain tests (14 test methods, 106 assertions)
- **`fixtures/pains/`** — JSON fixtures generated by the tests, compatible with the POC playground

## The 5 pains

| Pain | Country | Current problem | How the AST solves it |
|------|---------|-----------------|----------------------|
| #4 | France | Sick leave doesn't reduce vacation accrual | `exists` iterates absences by type → accrual = 0 when sick |
| #1 | Italy | H2 hire date gives fewer vacation days in first year | `tenure_years` + `hire_date.month` with `if`/`and`/`lt`/`gt` |
| #5 | Spain | Rounding to half-day / quarter-day precision | `round` node with `step=0.5` or `step=0.25` |
| #2 | DACH | Part-time accrues proportional to contracted hours | `mul` with `facts.contract.fte_ratio` |
| #3 | Global | Contract change FT→PT mid-year | Same program as #2 — the FactBuilder resolves the active contract per period automatically |
